🔒 PhantomDrive Security Audit

Score: 5.5 / 10
$65 CAD CH569W RISC-V AES-256-XTS Open Source (MIT) 📅 Aug 2026
Open-source encrypted USB drive with a stealth hidden partition. Appears as a normal 8GB stick until you write password:YourPass to unlock AES-256 encrypted storage. Full firmware source code reviewed.

What It Is

PhantomDrive is built by Ryan Walker (o7-machinehum) at Rootkit Labs. It uses a WCH CH569W RISC-V microcontroller with USB 3.0, SDIO, and a hardware AES block. The device presents as an ordinary 8GB flash drive, but hides a second encrypted partition that only appears after authentication.

Verdict: Brilliant proof-of-concept with solid crypto and genuine stealth. But no secure boot, no firmware signing, no data integrity. Great teaching tool for Brain Dump labs, not primary security for Bitcoin storage.

Findings at a Glance

✅ Strengths
  • Standards-based crypto (SHA-256, PBKDF2, AES-XTS)
  • Hardware AES acceleration (no timing side-channels)
  • Test vectors verified against OpenSSL
  • Genuinely invisible hidden partition
  • Fully open source (MIT), hardware designs included
  • Per-device salt from chip unique ID
  • Configurable KDF: 100K or 600K iterations
🔴 Critical Risks
  • No secure boot — firmware replaceable via USB
  • No data integrity — no HMAC/AEAD, bit-flip possible
  • No firmware signing or anti-rollback
  • Plaintext password over USB (keyloggers capture it)
  • Unvalidated AES hardware — WCH chip, zero certification
  • No rate limiting on failed unlock attempts
  • Default 100K KDF iterations too low

🎲 Entropia RNG Analysis & Better Methods

Analog Entropy Deep Dive
BIP39 Physical RNG Dice vs Pills Hash Extraction 📅 Aug 2026
Entropia generates Bitcoin seeds via physical lottery — drawing 3D-printed pills from a jar. Trustless and analog, but the physical draw introduces measurable bias. Analysis of the weaknesses and 5 better approaches to analog entropy generation.

How Entropia's RNG Works

Entropia is a physical lottery system. 1,024 double-sided pills in a jar, each face carrying one BIP39 word. You shake, draw 11 or 23 pills, read one side per pill, and feed those words into a SeedSigner which calculates the final checksum word to complete a valid BIP39 seed.

The entropy comes entirely from the physical draw — no computer, no PRNG. This is appealing because it's trustless: you don't rely on a chip or software to be honest about randomness.

The core question: Is physical randomization of pills in a jar actually uniformly random? Short answer: No. Physical lottery systems have well-documented bias.

Why Physical Drawing Is NOT Uniformly Random

🔴 Bias Sources
  • Weight variance: Infill differences, layer seams → heavier pills sink, drawn less
  • Friction / static: PLA on glass builds charge → pills clump, drawn in clusters
  • Container geometry: Pills near walls/bottom drawn less than center/top
  • Human bias: Unconscious favoring of depth, region, orientation
  • Side selection: Which face you read is a 1-bit systematic bias per word
  • Without-replacement skew: Distribution shifts after each draw
🔴 Why This Matters
  • A perfectly random 12-word seed = 128 bits of entropy (2¹²⁸)
  • A 10% bias on word selection can reduce effective entropy to ~100 bits
  • An adversary who knows the bias distribution can reduce the keyspace
  • You can't verify entropy quality after the fact
  • Each 3D-printed set has its own unique bias fingerprint
  • Layer lines, stringing, dimensional tolerance all vary per print

5 Better RNG Methods

Method 1: Casino-Grade Dice (Gold Standard)

Precision dice are manufactured to ±0.0001" tolerance — orders of magnitude more uniform than 3D-printed pills (±0.1mm). SeedSigner already has a built-in dice-roll mode.

Dice TypeBits / RollRolls for 12-wordRolls for 24-word
D6 (standard)2.58550 rolls99 rolls
D103.3239 rolls78 rolls
D164.032 rolls64 rolls
D204.3230 rolls60 rolls

✅ Recommended approach: Roll D6 50 times, input to SeedSigner. Cheap, verifiable, uniform.

Method 2: Entropia + Dice Hybrid

Use pills for word selection, but add dice entropy as an unbiased remix layer. Even if the pill draw is biased, the dice rolls ensure full entropy through SHA-256:

Workflow:
1. Draw 11 pills as normal → record words
2. Roll D6 20+ times to generate random salt
3. Feed SHA256(pill_words ‖ dice_rolls) into SeedSigner
4. Final seed = hash output (uniform regardless of pill bias)

Method 3: Hash Extraction (Debias Any Source)

Take any physical entropy source — pills, coin flips, card draws — and run it through SHA-256. The hash acts as a randomness extractor: biased input → uniform output, as long as there's sufficient min-entropy.

StepAction
1. CollectDraw pills, flip coins, roll dice — any analog source
2. Serializeinput = "pill1_word_a|pill2_word_b|..."
3. Hashseed_entropy = SHA256(input)[0:16] (16 bytes = 128 bits)
4. ConvertMap 16 bytes to 12 BIP39 words (11 + checksum)

Catch: SHA-256 doesn't create entropy — it just distributes what's there. If input has 100 bits of effective entropy, output has ≤100 bits. Use enough input.

Method 4: Multi-Round XOR Debiasing

Draw pills multiple times and XOR the results. Each round's bias is independent, so XOR significantly reduces total bias — same principle as Intel's RDRAND whitening:

Workflow:
Round 1: Draw 11 pills → convert to 128-bit number A
Reshake, Round 2: Draw 11 pills → convert to 128-bit number B
Final entropy = A XOR B (bias drops quadratically)
Optional Round 3 for even better uniformity

Method 5: Commitment Scheme (Verifiable Fairness)

Prevent any party — including the SeedSigner itself — from biasing the result using a cryptographic commitment. Same principle as coinjoin coordinators:

StepAction
1. You commitDraw pills, hash the words, write down hash H₁
2. SS commitsSeedSigner generates nonce, shows hash H₂
3. RevealBoth reveal values
4. Final seedSHA256(your_words ‖ SS_nonce)

Neither party could bias the result because both committed before revealing. This is how coinjoin coordinators prevent input bias.

✅ For Actual Seed Generation
  • Use precision dice (D6 or D10), not pills alone
  • SeedSigner has built-in dice mode — roll 50× D6, done
  • If using Entropia, always pair with dice or hash extraction

Overview

ps5-linux transforms your PS5 (Phat and Slim) into a fully-functional Linux PC. By leveraging patched hypervisor vulnerabilities, you can unlock the full hardware potential — 8 CPU cores at 3.5 GHz, GPU at 2.23 GHz, HDMI 4K60 output, M.2 SSD support, all USB ports, Ethernet, and even internal Bluetooth.

This is a soft-mod: the internal SSD is not modified, and you can continue using your PS5 normally. You'll need to re-run the exploit each time you want to boot into Linux.

Performance: Capable of running Steam games and various emulators with fluidity on a AMDGPU-powered Linux desktop.

Firmware Compatibility

ps5-linux only supports specific firmware versions on PS5 Phat and Slim. If you're on an unsupported firmware, you may need to update — downgrading is not possible.

  • Disable HDMI Device Link: Settings → HDMI → Enable HDMI Device Link = Off

IMPORTANT: If you reset your PS5 settings or reinstall firmware, you must reapply these settings. Failure to enable rest mode USB power will prevent Linux from booting.

  • Disable automatic error reporting: Settings → System Software → Report System Software Errors Automatically
Getting a Linux Image

Option 1: Download Pre-built Image (Recommended)

Download from ps5-linux-image releases. Recommended: ps5-ubuntu2604.img.xz. Unpack the .xz file (use 7-Zip on Windows or xz -d on Linux).

Option 2: Build Your Own Image

Requires WSL on Windows or a Linux machine with Docker:

# Install WSL (Windows)
wsl --install

# Install Docker (Linux/WSL)
sudo apt update
sudo apt install docker.io -y
sudo service docker start
sudo usermod -aG docker $USER

# Build image
cd ~/
git clone https://github.com/ps5-linux/ps5-linux-image
cd ps5-linux-image
chmod +x ./build_image.sh
./build_image.sh --distro ubuntu2604

Result: output/ps5-ubuntu2604.img

Flashing the Image to USB

Drive must be at least 64GB. External SSD strongly recommended.

Linux/macOS

# Check drive name first with lsblk (Linux) or diskutil list (macOS)
sudo dd if=output/ps5-ubuntu2604.img of=/dev/sdX bs=4M status=progress conv=fsync

Windows (Balena Etcher)

Download Balena Etcher, select the .img file, select your USB drive, click Flash.

WARNING: This will erase all data on the target drive. Double-check you've selected the correct device.

Jailbreak (Firmware 3.00-5.50)

Uses umtx2 exploit with fake DNS/HTTPS server.

Steps:

  1. Clone umtx2: git clone https://github.com/idlesauce/umtx2
  2. Configure dns.conf to point manuals.playstation.net to your PC's IP address
  3. Run fake DNS: sudo python fakedns.py -c dns.conf
  4. Run HTTPS server in another terminal: sudo python host.py
  5. On PS5: go to Settings → Network → Advanced Settings → set primary DNS to your PC's IP, secondary to 0.0.0.0
  6. Go to User Manual in Settings, accept untrusted certificate, run the exploit
Jailbreak (Firmware 6.00-7.61)

Uses Y2JB exploit.

Steps:

  1. Install Y2JB by following the official instructions
  2. Run kernel exploit: python3 payload_sender.py $PS5IP 50000 payloads/lapse.js
Sending the Payload

After jailbreaking, you need to send the ps5-linux-loader payload.

Download or Compile

  • Download: ps5-linux-loader.elf
  • Or compile: clone repo, run make (requires ps5-payload-sdk)

Send via socat

# Get your PS5 IP from the exploit page
socat -t 99999999 - TCP:$PS5IP:9021 < ps5-linux-loader.elf

Boot Behavior

If successful, the PS5 will automatically go into rest mode. Wait until the orange LED stops blinking and becomes static, then press power to boot into Linux. The LED should turn white if successful.

Troubleshooting

  • Boots back to PS5 OS: you pressed power too early, or rest mode settings not applied
  • Freezes instead of rest mode: disable etahen/kstuff (incompatible)
  • White LED but black screen: try removing video=DP-1: from cmdline.txt, toggle HDCP, try different monitor, set amdgpu.force_1080p=1

M.2 SSD Installation

You can use an M.2 SSD exclusively for Linux (cannot be used for PS5 game storage simultaneously).

Steps:

  1. Attach M.2 SSD following official guide
  2. If previously used for games: reformat on PS5 under Settings → Storage → M.2 SSD Storage
  3. Boot Linux and initialize M.2: cd ps5-linux-tools && sudo ./m2_init
  4. Reboot: sudo reboot. If asked to format again, report to Discord with M.2 model/size
  5. Relaunch Linux, install image to M.2: cd ps5-linux-tools && sudo ./m2_install.sh --install $PATH_TO_IMG
  6. Boot from M.2: cd ps5-linux-tools && sudo ./m2_exec.sh

Always Boot from M.2

Edit /boot/efi/cmdline.txt on the FAT32 partition: change root=LABEL=ubuntu2604 to root=LABEL=ubuntu2604-m2. USB still required (FAT32), but ext4 partition can be reformatted.

Fan & Boost Control

Enable max performance (3.5 GHz CPU, 2.23 GHz GPU) and adjust fan curve:

cd ps5-linux-tools
sudo ./ps5_control --fan on
sudo ./ps5_control --boost on

Always enable fan when boosting — this is what the official PS5 OS does.

FAQ
Q: Will firmware ≥8.00 be supported?

A: No.

Q: Why no M.2 on 3.xx firmware?

A: PS5 fails to boot with M.2 attached on those versions.

Q: Can I dual-boot Linux and PS5 OS?

A: No, this is a soft-mod. Re-run the exploit to boot into Linux. Internal SSD is not modified.

Q: Can I put Linux into standby and resume?

A: No, not currently supported. A shutdown-into-rest-mode feature may be added.

Q: Can I continue using my PS5 if I install Linux?

A: Yes, internal SSD is untouched.

Q: Does the DualSense controller work?

A: Yes, via internal Bluetooth or Bluetooth dongle.

Q: What resolutions/refresh rates are supported?

A: 1080p, 1440p, and 2160p at 60Hz are broadly supported. 1440p@120Hz confirmed on DELL S3225QC only. 120Hz/30Hz may be added.

Q: After reboot, I get "Repairing" / "Your PS5 wasn't turned off properly." Is this normal?

A: Yes, and it's harmless.

Q: Can I use the PS5's NIC/WLAN module in Linux?

A: Ethernet is supported on all models. WLAN only for Marvell chipsets currently.
